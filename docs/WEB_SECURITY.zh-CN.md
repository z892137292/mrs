# 架构与验证范围

浏览器 → 独立 Web Express → Bearer 保护的内网 agent → 固定 rewards-ctl 命令；调度依然由 rewards 原 supercronic 执行，任务依然同一个 flock。无 Docker Socket，无账号/会话共享挂载。agent 与核心同一非 root UID/PID命名空间，读取原记录；Web 有自己的 SQLite 存储。

启动/结束事件 hook 有2秒超时、失败不改变任务结果，不触发网络。通知发送在 Web 队列独立进行。agent故障不终止调度，Web显示不可达；没有自动从API失败重新执行任务。人工恢复持有原锁，并要求密码核查和60秒一次性二次确认。普通pause的noclobber避免覆盖风险STOP，这是定点安全修复，三份上游补丁不改。

SQLite 会话、登录限速（重启仍保留）、审计和发送结果持久化；会话8小时、日志下载最多256KiB并再次脱敏。来源Origin+CSRF严格检查，CSP只允许自身脚本，界面使用textContent，不执行innerHTML。设置只读，不接受任意命令。所有修改请求记录审计，含失败。

JSON摘要字段只允许明确的UI字段；不会返回整个config、env、sessions、diagnostics。积分来源明确，上游摘要不等于独立余额。账号ID为邮件摘要的截断SHA-256，仅作为显示关联，不是授权凭证。新通知存储仅由Web用户可读，不提供无管理员认证的配置/记录接口。

CI测试清单：干净上游补丁编译与14项回归、包装器互斥/失败重试/超时/熔断/风险、备份恢复；Web初始化/授权/CSRF/登录限速/重启、账号与日志脱敏、任务手动与计划冲突、人工风险恢复；真实本地HTTP/SMTP成功/失败/有界队列；两个真实amd64镜像、非root权限、真实Chromium打开页面和响应布局、独立Web停止不影响调度、容器停止/重启；原真实Chromium120秒回归。结果以实际Actions记录为准。

本地沙箱PID与/proc条件不匹配会标记跳过；CI不得跳过。多日资源/磁盘趋势、NAS具体ACL/代理/防火墙、公网Telegram/真实邮箱投递、真实微软页面/积分、版本会话回滚未实测时必须标注未验证。不称为长期正式稳定版，发布候选版并保留旧版。
